# legacy/

**Superseded material, kept with standing.**

Nothing filed here is retracted. A claim that was made, tested, and replaced is not the
same as a claim that was never made — it holds **precedence**. It establishes what was
already tried, when, by whom, on what evidence, and what it cost to find out. That is
worth something to whoever comes next, including whoever comes next inside this repo.

The ledger of those claims is **[PRECEDENCE.md](PRECEDENCE.md)** — the ones that were
replaced and the ones that held. It is the substance of this folder; the folder itself is
mostly a promise about where things go.

---

## The cycle this folder records

Hypothesize → run → result → edit the claim → search for what the result opened → rerun.

The repo already does this. What it did not have was one place to read the loop end to
end. Each turn was legible only to someone who had read all six documents and the commit
log. `PRECEDENCE.md` is that place.

Two things the ledger deliberately keeps that a cleaner record would drop:

- **Predictions that were confirmed**, not only the ones that failed. A confirmed
  prediction is precedence too, and a ledger holding only failures reads as
  self-flagellation rather than as a record.
- **The date and the wording as committed.** "We used to think X" is not precedence.
  "On 2026-08-12 this repo committed X, in these words, before seeing the response" is.

---

## What comes here

A file is a candidate when it is **whole material that something else now replaces**:

1. A document superseded by another document, where the old one was published and may
   still be linked.
2. Content consolidated elsewhere under [one home per
   idea](../CLAUDE.md#editorial-rules), where the emptied file had readers.
3. A frozen version of a dataset or protocol, where the old version is needed to read
   results that were produced against it.

## What does not come here

This matters more than the intake rule, because the obvious readings of "archive the
superseded stuff" would destroy the repo's primary evidence.

- **Failed `analystReading`s stay in `collisions.js`**, next to the
  `practitionerCorrection` that overturned them. The juxtaposition *is* the finding — that
  the analyst layer makes the same class of error as the instruments it studies. Separating
  the two would leave a corrected record that looks as though it was right the first time.
- **Failed sentences in prose stay where they were written.** The "cost four generations"
  sentence is kept, uncorrected, in two files on purpose. Do not collect them here.
- **Primary sources never move.** A later practitioner entry does not supersede an earlier
  one; both are things that were said.
- **Unrun is not superseded.** `ATTRIBUTION_PROBE.md` is drafted and has never been
  administered. That is pending, not legacy.
- **Edited-in-place data is not moved.** A downgraded confidence tag in `data.js` is an
  edit to a live dataset; log the downgrade in `PRECEDENCE.md` and leave the file alone.

**The governing test:** if moving something would separate a failed claim from the
correction that replaced it, do not move it. Log it in `PRECEDENCE.md` instead. The ledger
exists so that "leave it in place" and "make the revision findable" stop being in
conflict.

## Current contents

**No files.** As of 2026-08-14 nothing in this repository qualifies. No file has ever been
deleted here, and every superseded claim to date lives inline next to its correction, where
the rules above say it belongs.

That is not a defect in the folder. The intake rule and the ledger are what was actually
missing; an empty archive with a stated rule is more useful than a full one with an implied
one. The dead filenames in [PRECEDENCE.md §S2](PRECEDENCE.md#s2--two-dead-filenames) are the
closest thing to an exception, and they are records rather than files — there is nothing to
move.
